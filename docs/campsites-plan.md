## 2. What RTG's site actually is (measured 13/10/2026)

| piece | where | notes |
|---|---|---|
| Campsite list | `secure-hotels.net/INPA/BE_Engine.aspx?lang=heb&hotel=13_1` → hidden `#settings` JSON | 18 campsites in 3 regions. **`OptimaResortID` is the booking id** (חאן בארות = 13, אכזיב = 23). `#engineSettings`: `RoomSelectMax 4`, adults ≤35, children ≤20, infants ≤4 |
| Info page per campsite | `parks.org.il/camping/<slug>/` (18 links on `/camping/` → redirects to `הזמנות-לחניוני-לילה`) | facilities (מה בחניון), hours, directions/Waze name, rental gear, **price tabs** רגיל · מנוי · חייל · מילואים · קבוצה · אזרח ותיק · סטודנט · נכה (all tabs are in the HTML; only the active one is visible) |
| Booking deep link | `secure-hotels.net/INPA/BE_Results.aspx?lang=heb&hotel=<id>&in=YYYY-MM-DD&out=YYYY-MM-DD&rooms=<n>&ad1=&ch1=&inf1=…` | Opens the real order page pre-filled: each composition, **live availability per lodging type, and full prices** (regular / מטמון / מילואים / חייל). Verified: חאן בארות 12–14/11, 2+3 → ₪538 regular = 2 nights × (2×64 + 3×47) |
| Availability API | `BE_Engine.aspx/getAvalibility` (POST JSON) | Behind a Cloudflare JS challenge: returned the challenge page headless. **Not used**; the results page is. |

**Gotchas**
- 🔴 **Cloudflare / CloudFront block plain HTTP** (curl → 403) **and the default headless user-agent.** A real Chrome with a normal UA passes. The crawler therefore drives Chrome; `requests` is not enough.
- **RTG rules for one order** (from the results page): at most **4 compositions**, all for **the same nights**, paid together at the gate (the first to arrive pays for all, or waits). A group with more families needs several orders.
- **Age bands differ by page.** The booking engine says פעוט up to 5 · ילד up to 18 · מבוגר 18+, but Achziv's price list said מבוגר 14+. **Prices come from the crawled price list; composition labels come from the engine.** Show both, and let the results page be the final word.
- Groups of 30–80 people paying together book through a **form** (תיאום לינה לקבוצות), not the engine. That is the group rate.
- Never submit an order automatically: it needs a credit card and personal details. We **open** the real page; the family finishes it there.

## 3. Decisions (derived: object if wrong)

| topic | decision | why |
|---|---|---|
| Data the site reads | `data/campsites.js` (`window.CAMPSITES`) and `data/availability.js` (`window.AVAILABILITY`), generated by the crawler and **committed**. Also `.json` copies for tools | Static site, no fetch, no CORS: renders instantly (the repo's "fast on the client" rule) |
| Trip config | `trip.js` (`window.TRIP`: campsite id, dates, apiUrl, group size). `prices.js` builds `window.CAMP` from `TRIP` + `CAMPSITES`, so `calc.js` and the backend stay unchanged | One switch point; `calc.js` already reads only `CAMP` |
| Price categories | Map the crawled tabs to the existing ids: רגיל → adult/child · מנוי → matmon* · מילואים → reserve* · חייל → soldier · סטודנט → student · אזרח ותיק → senior · נכה → idfDisabled · קבוצה → `groupPrice`. A tab missing on a campsite = that category hidden there | Keeps the calculator and the sheet's columns as they are |
| Crawler | `crawler/` in this repo: `crawl.py` (Python + `playwright`, `channel="chrome"`, so no browser download), sequential, 3–5s between pages, normal UA | Polite; one PC; Chrome passes Cloudflare |
| Schedule | Windows task **CampWebsite crawler**: info daily at 05:30; availability for the current trip every 6h until the trip ends. Commit + push only on a real diff | Live site updates about 1 minute after a push; nothing costs money |
| Monitoring | Each run appends to `crawler/runs.log` (time · pages · changes · errors) and writes `checkedAt` into the data. The site shows "עודכן ב-dd/MM HH:mm" and flags data older than 3 days | "If it silently never runs, what makes me notice?" The site itself |
| Registrations per trip | The backend gets a `trip` field; each trip's registrations live in their own tab (`הרשמות <tripId>`). Achziv's rows stay where they are, as trip `achziv-2026-10` | A family registered for Achziv must not log in to November with October's nights |
| Booking helper | A **הזמנה ברט״ג** panel: number of families, each family's composition (מבוגרים · ילדים · פעוטות in the engine's bands), dates from the trip. Split into orders of ≤4 families; one **פתיחת ההזמנה באתר רט״ג** button per order (deep link). Prefill from our registered families | "Imitate RTG registration" without imitating payment |
| Availability shown | From the last crawl, per lodging type, labelled with its time, plus the live deep link | The page can't call RTG itself (CORS + Cloudflare) |

#### 5.3 Site: trip config from the data

Design (13/10/2026, refines the "Trip config" row in §3):
- **`trip.json`** (root, committed) is the one switch: current trip `{id, campsiteId, from, to, title, dateRangeStart/End, maxConsecutiveNights, groupMinPeople, apiUrl}` + `past[]` (Achziv = `achziv-2026-10`, campsite 23). The crawler reads the same file (only `id/campsiteId/from/to`). If the crawler branch also created a smaller `trip.json`, keep this one (it is a superset).
- **`tools/trip.py`** generates **`prices.js`** (`window.CAMP`, same shape as today, plus `tripId`, `campsiteId`, `name`) and **`trip.js`** (`window.TRIP`: the trip + its campsite record for header/place tab) from `trip.json` + `data/campsites.json`; `--check` mode joins the gates. So `calc.js`, `admin.js` and `build.py` stay unchanged. Category labels/notes come from a template in `trip.py` (today's `prices.js` wording); ages from the price-row notes when present (Achziv: "גיל 14 ומעלה"), else no age text. A category whose rate is null at that campsite is left out (toddler and escort stay, at 0). Mattress extra from `rentals`.
- **Tests stay pinned to Achziv:** copy today's `prices.js` to `tests/fixtures/prices-achziv.js` (+ a `trip-achziv.js`). `calc.test.js` loads the fixture; `backend.test.js` re-runs the fixture + `calc.js` in its vm after loading `Code.gs` (line ~1070 asserts Achziv prices); every e2e test routes `**/prices.js*` and `**/trip.js*` to the fixtures through one helper `tests/pin-trip.js`, so their October dates keep working.
- **Registration stays OFF for the new trip until Yair deploys the trip-aware backend** (§5.5 backend box). Without it a November save under an October name+code would overwrite the October row (the organizers' שולם reconciliation). The site sends `trip`; a backend that does not echo `trip` back means "old server", so the calculator works and saving shows "השרת עוד לא עודכן".
- `activities.js` has `TRIP = {from:'2026-10-06', to:'2026-10-13'}` hardcoded: read it from `CAMP`. Place tab: replace the hand-written Achziv HTML with a renderer from `TRIP.campsite` (Achziv's text stays in git history). Waze/Maps by name: `https://waze.com/ul?q=<waze>&navigate=yes`, `https://www.google.com/maps/dir/?api=1&destination=<waze>`.
